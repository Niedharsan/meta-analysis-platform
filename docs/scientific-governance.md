# Scientific governance

The platform treats model output as proposed evidence, not as scientific truth.

## Review states are explicit

Extraction candidates and materialized scientific rows have explicit non-approved states. A row is curated only after a human review transition to an approved state. Automated verification can make evidence review-ready but cannot approve it.

## Provenance is part of the evidence record

Reported evidence is linked to its project, study, report and supporting source location. Approval checks require attributable provenance. Derived evidence instead retains explicit links to approved inputs.

## Missing values remain missing

Unreported measurements, dispersion values, sample sizes and event counts are not converted to zero. A reported zero is represented separately from missing information.

## Scope is enforced

Candidates, provenance and scientific records are checked against their project and study context. Cross-project and cross-study references are rejected.

## Corrections are auditable

Review transitions are recorded. Where scientific content changes, the full system can create a successor version and mark the previous row as superseded instead of silently overwriting it.

## Analysis inclusion is analysis-specific

Approval does not make a row suitable for every analysis. Included and excluded evidence is recorded against an analysis-specific evidence set, together with the relevant calculation snapshot.

## Project rules remain project-specific

Reviews can use different search methods, eligibility rules, target variables, appraisal procedures and analysis plans while sharing the same evidence infrastructure. Those scientific rules are versioned project configuration and are not published here.

The exact CSP protocol and CRISPR production configuration remain private.
